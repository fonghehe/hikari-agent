# Agent 可靠性、评测与交付

本页描述 2026-11-14 的运行机制和验证边界。共享入口为 `prepareAgentSession`，桌面、CLI、Worker 和评测使用相同的能力组装。测试夹具的通过率不能作为真实模型成功率发布。

## 崩溃与未知操作

控制状态仍使用原子替换的 JSON 文件；跨进程短事务改用每个状态键的 `.json.lock.sqlite` SQLite 系统锁。活进程互斥，进程被强制结束后系统释放锁。旧版无归属信息的 `.json.lock` 不会被自动删除，必须先检查旧执行者。仅支持本机文件系统，不承诺网络共享盘或掉电后的磁盘持久性。

检查点保存操作记录、参数指纹、执行状态与恢复结果。工具适配器可声明只读、可安全重复或有副作用，并提供**只检查状态、不重复执行动作**的核对函数。`write_file` 会核对当前内容和原写入前置哈希。外部 MCP 的文字声明不能自行获得可信恢复权限。

`operation_status` 查看操作，`reconcile_operation` 使用可信适配器核对。核对独立经过权限检查：已成功的副作用不能重复执行；确认未发生的动作可重新尝试；未知结果不能由模型声明为已解决。没有适配器时保留人工检查入口。未知结果会保留为阻塞交付，不自动结束工单。

记录每任务最多 2,000 项。指纹只能识别相同工具与规范化参数，不能保证参数不同但语义相同的动作不重复，也不代表第三方系统的通用 exactly-once 保证。无内置核对器的外部写操作仍需人工核对。

## 记忆与攻击流程

`remember` 和 `forget_memory` 使用独立的 `memory.write` 权限；普通文件写权限不能自动批准它们。写入保存提议任务和时间，来源仍是参考数据。桌面扩展面板中由用户直接发起的编辑、删除保持为明确用户操作。

安全回归使用模拟恶意网页/MCP 返回内容及已污染的项目记忆，并让协议夹具主动尝试保存用户级权限、越界写文件及连接未批准 MCP，检查实际数据和权限结果。这验证运行时边界，不证明真实模型能够抵抗所有提示注入。工作区内已经授予的能力仍需任务质量评测、审阅与最小权限共同约束。

## 四类任务基准

`pnpm eval:agent --list` 列出 24 项受控任务：修 Bug、兼容性重构、项目问答、固定资料调研各 6 项。真实模型通过 `SessionHost` 运行；能力评测通过共享会话入口运行，包含生产授权、工具和上下文成本。评测使用明确的本地权限策略，不打开额外网络；浏览器能力探针单独批准其本地交互。

```sh
pnpm eval:agent --validate
pnpm eval:agent
pnpm eval:report REPORT.json
```

第一条只检查错误基线和参考结果。第二条需要显式配置模型，会消耗额度；本轮工程验证没有运行付费模型。每轮任务隔离，固定检查器留在可写工作区外，不把检查器命令放进模型的验收配置。

问答和调研使用只读 Plan、固定文档和结构化事实/来源检查。它们验证事实、冲突、未知信息和引用，但不能替代开放式语义评审或实时网页研究。重构检查兼容导出和行为；仍应通过 `eval:repository` 增补真实项目固定提交案例。

报告区分有效任务失败和环境/服务无效运行。门禁增加四类覆盖与无效运行率，避免仅报告排除请求失败后的高成功率。默认整体与逐案例成功率 90%、每案例 3 次、P95 180 秒、至少 5 个案例，且四类各至少 1 案例、无效比例最多 10%。可配置：

| 变量                                  | 含义                                                             |
| ------------------------------------- | ---------------------------------------------------------------- |
| `EVAL_REQUIRED_CATEGORIES`            | 默认 `bugfix,refactor,qa,research`；只检查某套专项报告时显式调整 |
| `EVAL_MIN_CATEGORY_CASES`             | 各类最低不同案例数                                               |
| `EVAL_MAX_INVALID_RATE`               | 服务或环境无效运行率上限                                         |
| `EVAL_MAX_MODEL_COST_PER_SUCCESS_USD` | 每次成功的已记录模型费用上限，包含有效失败尝试的费用             |
| `EVAL_MAX_MEAN_INTERVENTIONS`         | 每次有效任务的平均人工介入上限                                   |

成本或人工指标缺失时，启用对应门禁会失败，缺失值不按零处理。模型费用门禁不涵盖第三方工具、基础设施或无法确认的服务账单。

## 可信交付

`Task.delivery` 独立记录产物、实际验收证据、未完成项、限制和人工操作入口。当前文件和最终答复带内容哈希；文件最多 64 项、每项最多 2 MB。模型提议的链接保留为未验证，不会自动访问；删除或不可读文件明确标为不可用。哈希证明记录的内容，不能证明内容正确。

界面区分已通过配置的验收、本轮无需执行验收、尚未独立验证、执行或验收失败。空检查不显示为独立验证通过；Plan/聊天可以无需执行验收。旧记录没有交付字段时仍可显示原有执行证据。原始最终答复保持用户要求的格式，交付元数据单独存储。

## 成本与人的注意力

运行汇总记录提问、审批、拒绝、人工介入数、等待/暂停时长及执行时长。重叠等待按并集统计总等待；恢复同一个问题不重复计数，应用关闭期间不计执行和等待。总任务时限仍包含运行期间等待。

缓存读写可配置独立单价：`cachedInputPerMillion`、`cacheWriteInputPerMillion`；CLI 评测对应 `AGENT_CACHED_INPUT_PRICE`、`AGENT_CACHE_WRITE_PRICE`。未配置时沿用输入单价并标记计费不完整。模型输出、缓存读写、子任务费用均为配置价格下的记录或估算，不是厂商发票。

主动事件研判单独持久记录调用、token、已知费用及未知账单，重启不会把未完成请求算作免费。监督面板/API 按工单汇总各派工、相关研判和人工介入。`assessmentBudget.maxCalls` 默认累计 1,000 次；可在明确策略中设置调用及美元上限。美元预算需要价格，未知账单会阻止继续按该预算自动研判。历史累计计数不因明细保留窗口而清零。

外部工具、嵌入/重排和基础设施收费尚未统一接入账单；模型重试在供应商端是否收费也可能未知。界面明确提示模型费用范围，不将它展示为完整任务总价。

代码检查器导入候选代码时也使用禁用网络的受限子进程，防止验证阶段绕过执行沙箱访问宿主文件。这保护宿主边界，不构成对所有评分作弊方式的形式化保证。
