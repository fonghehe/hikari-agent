# MCP と Skills

拡張機能を使う前に実際のモデルを接続し、ワークスペースを開きます。オフラインデモは外部ツールを接続せず、プロジェクトの Skill も読み込みません。

サイドバーの **メモリーと拡張機能** から HTTP または stdio MCP を追加し、名前と URL またはコマンドを入力します。引数は 1 行に 1 件です。HTTP 認証トークンは OS 暗号化が利用できれば別に暗号化保存し、利用できなければメモリー内だけに保持します。プロジェクト設定やモデルへ送信しません。同じ画面で削除できます。変更は新しいタスクに適用されるため、作業中のタスクを終了してください。

**スキルフォルダーを読み込む** で `SKILL.md` を含むフォルダーを選びます。説明を確認し、不要なら削除できます。シンボリックリンク、名前の重複、100 ファイルまたは 20 MB 超のインポートは拒否します。インストール時にはスクリプトを実行しません。

接続した MCP のツール、リソース、プロンプトを利用できます。列挙されたリソースの読み取りやプロンプトの取得を依頼してください。承認は引き続き必要です。内容は参考資料であり、ユーザーの指示を上書きできません。

以下のファイル設定も利用できます。

## MCP サーバーを追加する

ワークスペース内の `.agent/mcp.json` に設定を保存します。次の例のコマンドや URL を実際の値に置き換えてください。

```json
{
  "local-tools": {
    "transport": "stdio",
    "command": "node",
    "args": ["/absolute/path/to/your/mcp-server.mjs"]
  },
  "http-tools": {
    "transport": "http",
    "url": "http://127.0.0.1:4320/mcp"
  }
}
```

1. 利用するサーバーの手引きに従ってインストールと設定を行います。
2. Hikari にワークスペースの MCP サーバー一覧を表示し、必要なサーバーへ接続するよう依頼します。
3. 接続リクエスト、コマンド、アドレスを確認し、信頼できる場合に許可します。
4. そのツールで行いたいタスクを説明します。

切断されたら再接続を依頼してください。設定を変更すると再承認が必要になる場合があります。認証情報はサーバーが提供する設定方法で渡し、タスクの指示には書かないでください。

## Skill を追加する

ワークスペースに `.agent/skills/frontend-review/SKILL.md` を作成します。

```md
---
name: frontend-review
description: Review frontend code without modifying files.
allowed-tools:
  - read_file
  - list_directory
  - glob
  - grep
  - search_code
  - git_status
  - git_diff
---

関連するコードを読み、再現できる問題をファイルパスとともに報告してください。
ファイルは変更せず、改善案を提示してください。
```

Hikari に Skill の一覧表示、`frontend-review` の読み込み、プロジェクトのレビューを依頼します。フォルダー名や説明は自分の作業に合わせて変更できます。指示には期待する結果を明確に書きます。

Skill のツール制限はタスク中も有効です。Skill を読み込んでも、承認が必要な操作が自動で許可されることはありません。
