# 自動実行・サブエージェント・開発環境との連携

デスクトップ、CLI、タスク実行基盤で共通の機能を利用できます。リモート実行には自分で登録したコンピューターやサーバーを使います。モデル、言語サーバー、実行環境は別途用意してください。Hikari が管理するクラウドアカウントが自動で作成されるわけではありません。

## 1. サブエージェントへの委任

実際のプロジェクトタスクでは `spawn_agent`、`wait_agent`、`send_agent_message`、`cancel_agent` を使用できます。独立した調査を委任し、ファイルに基づく根拠を集めるよう指示してください。各担当者は独立したコンテキストを持ち、親タスクのツール制限を引き継ぎます。同時に三人、実行全体で十二回まで委任でき、入れ子の委任はできません。

既定では読み取り専用です。`writable: true` を指定すると、未コミットの内容を含む専用 Git ワークツリーを作成します。変更はそこに残り、元のプロジェクトへ自動反映されません。差分を確認してから既存の反映手順や Git を使用してください。依存パッケージと無視対象のファイルはコピーされません。

親タスクは残りのトークン・費用の一部を予約し、担当者の実使用量を計上します。完了前に担当者を待機し、親が中断・キャンセルされると担当者も中断します。結果が不明な操作は自動で再実行しません。Plan モードでは委任できません。

プラグインで役割を追加できます。`examples/plugin` には `project-review-reviewer` の例があります。役割の指示だけでレビューの正確性が保証されることはありません。

## 2. ライフサイクルフック

**設定 → 記憶と拡張機能 → 自動実行と連携 → ライフサイクルフック**、または `.agent/hooks.json` で設定します。

```json
[
  {
    "id": "format-source",
    "event": "PostToolUse",
    "tool": "apply_patch",
    "command": "node",
    "args": ["scripts/format.mjs"],
    "timeoutMs": 30000
  }
]
```

イベントは `SessionStart`、`PreToolUse`、`PostToolUse`、`Stop` です。省略可能な `tool` はツール名と完全一致します。コマンドの標準入力に、イベント・タスク・ツール呼び出し・結果を含むサイズ制限付き JSON を渡します。シェル展開は行いません。

通常のコマンド承認とサンドボックスが適用されます。承認拒否、失敗、タイムアウトは操作を止めますが、実行済みの副作用は取り消せません。フックの編集も変更履歴に記録し、以前のテスト結果を無効にします。`Stop` は最終検証の前に実行します。

Plan モードと開発ワークフローの読み取り専用段階では実行せず、書き込み可能な実装段階から開始します。設定の変更は次の実行に適用されます。無人実行でも承認を迂回できません。

## 3. スケジュールと監視

**スケジュール実行** で繰り返しや一度だけの実行を登録します。デスクトップは登録されたプロジェクトと作成時のモデル設定を保持します。コンピューターとアプリを起動したままにしてください。通知は変更・失敗時、毎回、失敗時のみから選べます。監視には、対応が必要な変化の条件と、変化がない場合の一定の返答を指示してください。

CLI の例として、次を `schedule.json` に保存します。

```json
{
  "name": "プロジェクトの変化を確認",
  "prompt": "対応が必要な変化だけを報告してください。なければ毎回『変更なし』と答えてください。",
  "cadence": { "kind": "interval", "minutes": 60 },
  "isolated": false,
  "notify": "changes",
  "options": { "mode": "plan", "maxTokens": 40000, "maxDurationMs": 300000 }
}
```

```sh
pnpm agent schedule add schedule.json
pnpm agent schedule list
pnpm agent schedule run
# schedule pause ID / resume ID / remove ID
```

一度だけなら `{"kind":"once","at":"2026-12-01T01:00:00Z"}`、cron なら `{"kind":"cron","expression":"0 9 * * 1-5","timezone":"Asia/Tokyo"}` を使用します。cron は五つのフィールドで、リスト・範囲・間隔を指定でき、曜日は 0–6 です。指定したタイムゾーンと夏時間に従います。今後一年以内に実行できない式は受け付けません。

一つのプロジェクトのスケジューラーは一プロセスだけが所有します。同じ予定は重複実行せず、逃した繰り返し分をまとめて扱います。クラッシュ時に実行中だった予定は復旧後に無効化します。保存したタスクの状態を確認してから再度有効にしてください。デスクトップと CLI で同じプロジェクトを同時に管理しないでください。CLI の通知は JSON イベントです。

無人 CLI はコマンドを既定で拒否します。`HIKARI_ALLOWED_COMMANDS='["node"]'` は、そのプログラムと引数で渡すスクリプトを選択したサンドボックス内で許可します。必要なものだけを設定してください。

## 4. 言語サーバー

対象言語のサーバーをインストールしてから、設定画面の **言語サーバー** または `.agent/lsp.json` に登録します。

```json
[
  {
    "name": "typescript",
    "command": "typescript-language-server",
    "args": ["--stdio"],
    "extensions": [".ts", ".tsx", ".js", ".jsx"],
    "languageId": "typescript"
  }
]
```

承認すると stdio の Language Server Protocol を使用して `lsp_definition`、`lsp_references`、`lsp_hover`、`lsp_diagnostics` を提供します。行と列は 0 始まりです。問い合わせ前に現在のファイルを送り、タスク終了時にサーバーを閉じます。サーバーからの編集要求は拒否し、プロジェクト外の位置情報は返しません。

起動はコマンド権限を必要とし、Plan モードでは使用できません。診断結果はサーバーとプロジェクト設定に依存します。プル型の診断に対応していない場合は配信済みの結果を使うため、まだ届いていないこともあります。コンパイルとテストも実施してください。Windows のサンドボックスでは Linux イメージ内にサーバーとツールチェーンが必要です。

## 5. VS Code

ソースは `integrations/vscode` にあります。`pnpm vscode:pack` を実行し、**拡張機能 → VSIX からインストール** で `release/hikari-workspace-0.1.0.vsix` を選択します。

同じプロジェクトでデスクトップのリモート操作を有効にするか、`pnpm agent serve 4319` を実行します。エディターの **Hikari: Connect to Local Host** で URL とトークンを入力してください。トークンは VS Code SecretStorage に保存します。

**Hikari Tasks** からタスクの開始、結果の閲覧、一時停止・再開・キャンセル、追加指示、質問と承認への回答、差分の表示ができます。新規タスクには選択テキスト・ファイルパス・診断結果を添付できます。未保存の内容は明示し、ディスク上のファイルは置き換えません。エディターと実行ホストには同じプロジェクトを指定してください。信頼されていないワークスペースでは開始できません。

専用拡張は VS Code 向けです。JetBrains では外部ツールから CLI を呼び出せますが、専用プラグインは含まれません。

## 6. 別の端末からのリモート操作

設定の **リモート操作** で有効にします。既定の接続先は `127.0.0.1:4319` です。トークンをコピーして画面を開くと、実行中のタスクへの追加指示・承認・回答ができます。過去のスナップショット同期とは別の機能です。

別の端末からは HTTPS のリバースプロキシか SSH トンネルを使ってください。ローカルネットワークを許可すると `0.0.0.0` にバインドしますが、接続時にはコンピューターの実際の IP またはホスト名に置き換えます。CLI は `HIKARI_REMOTE_HOST=0.0.0.0 pnpm agent serve 4319` です。

トークンはプロジェクトを操作できる秘密情報です。停止すると自動生成されたトークンは無効になります。CLI では 32 文字以上の `HIKARI_REMOTE_TOKEN` を指定できます。API は `Authorization: Bearer TOKEN` を使い、URL のトークンは受け付けず、ブラウザーの Origin も確認します。

実行ホストを起動したままにしてください。接続を失った後は再接続でき、中断した実行は実際の状態を調べてから再開します。VS Code も同じ API を使用します。

## 7. 自分のサーバーでのクラウド実行

API サーバーに Node 24 と依存パッケージを用意し、`pnpm server` を実行します。外部公開には HTTPS を設定してください。保存先は `SQLITE_PATH` または `DATABASE_URL`、Redis は任意です。`/execution` はスマートフォンでも使えるジョブ画面です。既存のアカウント同期フローか `/auth/register` で作成したアカウントでログインします。

実行マシンには Git、ripgrep、モデル設定と OS サンドボックスを用意し、プロジェクトの別名を準備済みのチェックアウトに対応させます。

```sh
export HIKARI_SERVER_URL='https://hikari.example.com'
export HIKARI_WORKER_PROJECTS='{"my-project":"/srv/projects/my-project"}'
export HIKARI_ACCOUNT_TOKEN='/auth/login の token'
pnpm agent worker register build-machine
```

返された `workerToken` を実行側の `HIKARI_WORKER_TOKEN` に設定し、`pnpm agent worker run` を起動します。`--once` は最大一件だけ処理する診断用です。モデルは通常の CLI と同じ `AGENT_*` 設定を使用します。ブラウザー機能には Chromium も必要です。明示的に許可していないコマンドはリモート承認を待ちます。

ジョブ画面でワーカーとプロジェクトを選び、送信・進行状況の確認・回答ができます。送信者が任意のホストパスやモデルキーをジョブに指定することはできません。ワーカーは所有アカウントと登録済み別名に制限されます。認証付き `DELETE /execution/workers/ID` で資格情報を失効できます。

ジョブは排他的で有効期限付きの実行リースを持ち、更新で延長します。指示は確認されるまで保持します。期限切れは中断として扱い、別ワーカーで自動再実行しません。私有チェックポイントとワークツリーは実行マシンに残し、サーバーにはサイズ制限と機密情報の除去を適用した表示スナップショットだけを送ります。個人のノート PC を閉じても、サーバーとワーカーが動いていれば継続できます。

既定では OS サンドボックスを使います。専用 Docker ワーカーでは `HIKARI_WORKER_EXECUTION=container` と `/.dockerenv` の確認によりコンテナー内のホスト権限を利用できます。この場合は独立したコンテナー自体が実行境界です。無関係なホストディレクトリや資格情報をマウントしないでください。ネットワークはタスク設定と `HIKARI_WORKER_ALLOW_NETWORK=true` の両方が必要です。

マシンの自動作成、任意リポジトリの取得、依存パッケージの自動導入、一般公開のマルチテナントホスティングは含みません。

## 8. プラグインとカタログ

設定の **プラグイン** で確認済みフォルダーをインストール・更新・削除します。`hikari-plugin.json` に名前・セマンティックバージョン・説明と、任意の `skills`、`hooks`、`agents`、`lsp`、`mcp` を記述します。例は `examples/plugin/hikari-plugin.json` です。スキル名は `plugin:skill`、役割と MCP 名は `plugin-` が接頭辞になります。引数の `${plugin}` はインストール先に展開されます。

```sh
pnpm agent plugin inspect examples/plugin
pnpm agent plugin install examples/plugin
pnpm agent plugin list
pnpm agent plugin update /path/to/new-version
pnpm agent plugin remove project-review
```

インストールでスクリプトを実行しません。シンボリックリンクと特殊ファイルを拒否し、200 ファイル、各 2 MB、合計 20 MB に制限します。SHA-256 で内容を固定し、変更した場合は再インストールが必要です。デスクトップは進行中のプロジェクトタスクが終わるまで更新を受け付けません。CLI でもタスクを先に停止してください。

カタログはローカルファイルまたは HTTPS で取得する JSON です。`plugins` 配列の各項目に `name`、`version`、`description`、`path`、`sha256` を指定します。相対パスはその JSON の場所を基準とします。`pnpm agent plugin registry registry.json` は候補の表示のみを行い、`plugin install PATH SHA256` で内容を確認して導入します。既存のリポジトリやファイルサービスで配布できますが、Hikari がオンライン市場を運営したり自動更新したりすることはありません。

### プラグインの配布

`pnpm agent plugin pack examples/plugin /tmp/project-review.bundle.json` で配布用ファイルと内容のハッシュを作成し、カタログ JSON と一緒に自分の HTTPS ファイルサービスへ配置します。相対 URL も使用できます。デスクトップで URL を開いて候補を確認し、表示された SHA-256 で固定したバージョンを導入・更新できます。リモート導入はハッシュ・名前・バージョンを確認し、パスの逸脱とリダイレクトを拒否します。CLI は `plugin registry https://example.com/registry.json`、続いて `plugin install https://example.com/project-review.bundle.json SHA256` です。

## 9. GitHub と CI

`integrations/github-action/action.yml` は、上限付きの読み取り専用レビューを実行し、JSON レポートのパスを返す composite action です。モデル・エンドポイント・秘密情報を指定します。結果コメントは `post-comment: 'true'` と適切な権限の `github-token` を明示した場合だけ投稿します。モデルキーは GitHub Secrets に保存してください。レビュー対象に合う checkout と比較元を用意し、信頼できない fork のワークフローに秘密情報を渡さないでください。

イベントによる起動には API サーバーの `HIKARI_GITHUB_WEBHOOK_SECRET` と `HIKARI_GITHUB_ROUTES` を設定します。ルートの項目は `repository`、アカウント ID の `owner`、`workerId`、`project`、`allowedActors`、任意の `postResults` です。GitHub の JSON webhook を `/integrations/github/webhook` に接続し、同じ署名シークレットを設定します。

Issue の新規作成・再オープンと、PR の作成・再オープン・更新に対応します。許可していないリポジトリと操作ユーザーは拒否し、配送 ID と安定したジョブ ID で重複を防ぎます。

ワーカーは GitHub API から差分や Issue を取得して読み取り専用でレビューし、PR のコードを checkout・実行しません。非公開リポジトリには実行側の `GITHUB_TOKEN` が必要です。`postResults: true` はコメントの投稿・更新を明示的に有効にします。処理が成功してもモデルの指摘が正しいとは限らないため、引用された実装を確認してください。

## 10. 会話とコードの履歴

**タスク管理 → 会話とコードの履歴** でチェックポイントを選び、内容を確認して会話・コード・両方を復元できます。会話を戻すと再開可能な中断タスクを作成します。過去の承認やテスト結果を有効なものとして引き継ぎません。コードだけを戻す場合、会話は維持します。

CLI は `pnpm agent timeline list`、`timeline preview ID`、`timeline restore ID code|conversation|both` です。会話を復元すると新しいタスク ID を出力するので、`pnpm agent resume ID` で再開できます。

実際の実行の前後に記録し、最大 100 件の索引を保持します。テキスト取得は合計 8 MB、一度の復元は 20 ファイルまでです。バイナリー、大きなファイル、権限の変更は外部で復元してください。直近の記録後に変更されたファイルは競合として扱い、ユーザーの新しい編集を上書きしません。私有メタデータ、依存パッケージ、外部での副作用は戻しません。取得できない場合は `timeline.error` に理由を記録します。長期保存には Git とバックアップも使用してください。

## 11. 継続する目標

**タスクのオプション → 検証と予算** に目標・継続回数・使用量の上限を設定します。CLI は `AGENT_GOAL` と任意の `AGENT_GOAL_CONTINUATIONS` です。

```sh
AGENT_GOAL='決済テストの失敗を修正し、検証を通す' \
AGENT_MAX_TOKENS=100000 AGENT_MAX_MINUTES=30 \
pnpm agent run '決済テストの失敗を調べる'
```

目標は私有チェックポイントに保存します。モデルは `update_goal` で完了の根拠を示し、通常の検証にも合格する必要があります。未完了の返答では同じ目標へ自動で進みますが、元のトークン・費用・時間予算は更新しません。一時停止、キャンセル、外部依存、モデル呼び出し回数と継続回数の上限は引き続き適用します。阻害要因や予算切れを完了扱いにはしません。

## 実行権と再接続

デスクトップ、CLI、実行ノード、書き込み可能な子 Agent、履歴復元は、共通の作業ディレクトリ占有記録を使います。同じディレクトリで同時に実行できるのは一つの実行者だけです。別の worktree は並行実行できます。別のホストを開いても、生存中のプロセスが保持するタスクを中断扱いに書き換えません。完了時や初期化失敗時に占有を解放し、プロセス終了後は次のタスクが回収できます。処理の自動再実行は行いません。

記録は `.agent/state/execution-owner.json` に保存し、同一マシンのローカルファイルシステムで使います。外部エディター、ネットワーク共有、異なるコンテナーの PID 名前空間は対象外です。すべての Hikari インスタンスに対応版が必要です。短いトランザクションには `.json.lock` を使います。その途中で異常終了した場合は書き込みを停止するため、実行者が残っていないことを確認してから管理者が残存ロックを削除してください。

実行ノードは一時的な接続失敗と HTTP 408、429、500、502、503、504 に対して間隔を延ばしながら再接続します。取得要求と状態更新には永続的な識別子を使い、処理後に応答が失われても別のジョブを取得したり、完了更新を重複させたりしません。再接続は最大 90 秒、かつ最後に確認した 120 秒のリースが切れる 5 秒前までです。認証やリースの拒否時は直ちに停止します。中断理由とタスク ID は実行ノードに保存し、Worker を再起動しても開始済みのモデル処理は再実行しません。

## 検証範囲

変更時は `pnpm check`、`pnpm build`、`pnpm docs:build`、`platform-*.test.ts` と関連するデスクトップ・ブラウザーテストを実行してください。制御されたモデル、LSP、GitHub のテストサービスは実行基盤と失敗処理を確認するもので、実モデルの品質を示しません。実際の言語サーバー、公開 webhook、HTTPS 配備、GitHub への投稿は、それぞれの環境での確認が必要です。

## 自己ホストの上限と運用

既定ではアカウントごとに待機・実行中のタスクを10件、実行ノードを5台に制限します。1件あたり200,000 Token、30分が上限です。`HIKARI_MAX_ACTIVE_JOBS`、`HIKARI_MAX_WORKERS`、`HIKARI_JOB_MAX_TOKENS`、`HIKARI_JOB_MAX_MS` で変更できます。予算未指定時は上限を補い、超過要求は拒否します。永続化されたバージョン付き予約で同時作成を調整し、失敗時の予約は最大60秒残ります。完了で実行枠は空きますが、履歴は別途管理してください。

`/ready` は DB と設定済み Redis を検査し、障害時に503を返します。`/health` は生存確認です。32文字以上の専用 `HIKARI_OPS_TOKEN` を設定すると、Bearer 認証付きの `/operations/status` で応答件数、累計時間、メモリを取得できます。未設定時は404です。本番エントリーポイントの構造化ログは本文、認証ヘッダー、URL クエリを記録しません。

課金、企業 SSO、ホスト型コンテナ管理、完全な監査基盤、SLA は提供しません。公開運用前に専用環境、負荷、バックアップ、アラート、復旧を検証してください。
