# Agent の信頼性・評価・成果

デスクトップ、CLI、Worker、評価は `prepareAgentSession` の共通構成を使用します。プロトコル用フィクスチャの成功率は、実モデルの成功率ではありません。

## 復旧と権限

JSON 状態の原子的置換を維持し、キーごとの `.json.lock.sqlite` SQLite システムロックで相互排他します。プロセスの強制終了でロックは解放されます。旧 `.json.lock` は所有者が不明なため確認が必要です。ネットワークファイルシステムや電源断の耐久性は保証しません。

チェックポイントに操作結果と引数の指紋を保存します。信頼されたアダプターだけが、操作を繰り返さず結果を照合できます。`write_file` は現在の内容と元のハッシュを照合します。`operation_status` / `reconcile_operation` で確認し、照合にも権限が必要です。成功済みの副作用は再実行せず、不明な結果は人の確認待ちとなります。MCP の説明文だけでは復旧権限を取得できません。最大 2,000 記録であり、異なる引数による意味上同じ操作の exactly-once 保証ではありません。

記憶の追加・削除は独立した `memory.write` 権限を要求し、提案元タスクを記録します。悪意のある Web/MCP 相当の応答、汚染された記憶を用いるテストは、権限昇格、ワークスペース外への書き込み、不許可接続を試します。モデルのあらゆるプロンプトインジェクション耐性を保証するものではありません。

## 評価と成果

`pnpm eval:agent --list` は修正、互換性を保つリファクタリング、プロジェクト質問、固定資料調査を各 6 件、計 24 件表示します。`--validate` は失敗基準と参考結果だけを検証します。実モデル実行は `SessionHost`、能力評価は共通の本番構成を使用し、独立検証器はエージェントの書き込み領域外に置きます。

質問と調査は読み取り専用 Plan で構造化された事実と引用を検証します。自由形式の意味評価やリアルタイム Web 調査の品質は別途検証してください。実プロジェクトは固定コミットの `eval:repository` で追加できます。

門限は既存の成功率・P95 に加え、`EVAL_REQUIRED_CATEGORIES`（既定 `bugfix,refactor,qa,research`）、`EVAL_MIN_CATEGORY_CASES`（1）、`EVAL_MAX_INVALID_RATE`（0.1）を使用します。任意の `EVAL_MAX_MODEL_COST_PER_SUCCESS_USD` と `EVAL_MAX_MEAN_INTERVENTIONS` は証拠がなければ不合格です。専門評価ではカテゴリを明示的に設定します。

`Task.delivery` は成果、検証、未完了項目、制限、人への引き継ぎを記録します。現在のファイル・最終回答にハッシュを付けますが正しさの証明ではありません。ファイルは最大 64 件、各 2 MB。提案 URL は未検証、読み取れない成果は利用不可。空のチェックは独立検証済みと表示しません。最終回答の形式は変更しません。

## 費用と人の注意

質問、承認要求、拒否、介入回数と待機・実行時間を集計します。重複する待機時間は合算せず、同じ質問の復旧は二重計上しません。アプリ終了中は除外しますが、実行中の待機はタスク期限に含みます。

キャッシュ単価は `cachedInputPerMillion` / `cacheWriteInputPerMillion`、評価では `AGENT_CACHED_INPUT_PRICE` / `AGENT_CACHE_WRITE_PRICE` を設定します。未設定なら入力単価を使用し、不完全な価格情報とします。能動イベントの判断は呼び出し・token・既知料金・不明請求を永続化します。`assessmentBudget.maxCalls` は累積 1,000 回が既定で、任意のドル上限には価格が必要です。不明請求後はその予算で自動判断を続けません。

外部ツール、埋め込み・再ランキング、基盤、プロバイダー再試行の不明な料金は完全には計測していません。表示は設定単価によるモデル費用で、請求書や総費用ではありません。今回の工程検証では有料モデル評価を実施していません。

コード検証器も、ネットワークを無効にした制限付き子プロセスで候補コードを読み込みます。これは検証時のホスト保護であり、あらゆる採点操作への形式的保証ではありません。
