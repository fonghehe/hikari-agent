# 実行・検証・再開

## 完了条件を決める

入力欄の **検証と予算** を開きます。**ファイル検証**（パス、存在の要否、任意の必須テキスト）または **テストコマンド**（実行ファイル、1 行に 1 件の引数、作業ディレクトリ）を追加します。テストも承認が必要です。信頼できるコマンドを使用してください。

設定した条件に失敗した Execute タスクは完了になりません。既定では最後のファイル変更後にテストの合格が必要です。文書編集などでは **検証条件のみ使用** を選べます。Plan は提案のみで検証コマンドを実行しません。

**検証合格／不合格** と実際のテスト記録を確認してください。合格は検証した条件を満たす証拠であり、すべての正しさを保証しません。

## 実行中に指示する

タスクの実行中にもテキストを送信できます。次の安全なモデルステップで適用されます。実行中のツールは先に終了する場合があります。添付は現在のターンが終わってから送信してください。

エージェントが質問したら選択肢を選ぶか、回答を入力します。回答まで実行は待機します。待機中もキャンセルできます。

## アプリ終了後に再開する

有効な保存状態のある未完了の実タスクは **中断** と表示されます。実際のモデルを接続し、タスクを選んで **再開** を押します。会話、ツール結果、計画、質問、予算を引き継ぎます。完了した操作を自動で繰り返しません。

操作の結果が記録される前に中断した場合、実際の状態を確認して続けるか質問します。操作は既に実行されている可能性があるため、再実行の前にファイルや外部サービスを確認してください。保存状態がない、または壊れている場合は再試行が必要です。キャンセルは変更を取り消しません。

## 使用量を制限する

送信前にトークン、USD 費用、時間の上限を設定します。空欄は追加上限なしです。再開しても予算はリセットされません。時間には回答や承認の待機も含みます。

費用上限には **モデル設定 → 使用量と互換性** の入力・出力単価を設定します。費用は設定単価による計算で、請求書ではありません。API が返した使用量は **プロバイダー報告**、返さない場合は **推定** と表示します。互換サービスの出力制限パラメーターとストリーミング使用量を調整できます。**接続テスト** は少量のトークンを使い、ツール呼び出しを確認します。

## コマンド権限を選ぶ

コマンドと stdio MCP は既定で **OS サンドボックス** を使用します。ワークスペースを変更できますが、許可されたワークスペースと実行環境以外の私有ファイルは制限します。**サンドボックスの通信を許可** を有効にするまで通信できません。ブラウザーと HTTP MCP も承認が必要です。

macOS はネイティブ機能、Linux は bubblewrap を使います。Windows は Docker Desktop をインストールし、チェックアウトで一度 `docker build -t hikari-sandbox:local -f containers/sandbox.Dockerfile .` を実行してください。コマンドは Linux コンテナーで実行します。必要なツールチェーンは派生イメージに追加し、同じタグを使用します。サンドボックスが使えない場合はエラーを表示し、自動でホスト権限に切り替えません。

必要なツールがサンドボックスで使えない場合だけ **ホスト権限** を選んでください。承認したホストコマンドと対話ターミナルはアカウントの権限で動作します。

## メモリー・Web・更新

有用なプロジェクトの事実や決定を保存するよう依頼できます。**メモリーと拡張機能** で内容を確認し、古い記録を削除します。メモリーはローカルの参考資料であり、指示を上書きしません。

通常の会話でも承認して Web ページを読めます。検索には JSON 出力を有効にした SearXNG `/search` の URL をモデル設定で指定します。質問を検索サービスに送信し、原文はブラウザーで読みます。未設定や障害時はエラーを伝え、検索結果を捏造しません。

**メモリーと拡張機能 → アプリの更新** に確認、ダウンロード、再起動を用意しています。更新先のあるパッケージ版が必要です。インストール前に実行中のタスクを終了してください。更新先がないローカルビルドでは、その制限を表示します。

## 開発ワークフロー

**検証と予算 → ワークフロー** で **調査 → 計画 → 実装 → レビュー** を選びます。調査と計画は読み取り専用で、変更やコマンド実行はできません。実装担当が引き継ぎを受け、承認済みツールで変更して検証条件を満たすと、独立した読み取り専用レビューへ進みます。問題があれば実装へ戻し、最大 3 回修正します。

段階、引き継ぎ、要約、未回答の質問はタスクとともに保存されます。再開しても段階と予算は継続します。レビュー担当は書き込み、コマンド、ブラウザー、外部 MCP を使用できません。レビューはモデルの判断です。実際のテスト証拠も確認してください。

## ワークツリーの反映

新しい実行タスクで独立ワークツリーを有効にします。開始状態は **HEAD** または **未コミットのファイルを含める** を選びます。後者では追跡済みファイルと Git の無視対象ではない未追跡ファイルをコピーします。元のファイルは変更しません。依存関係と無視対象はコピーしません。必要な準備は承認が必要なタスクのコマンドとして依頼します。リポジトリには少なくとも 1 件のコミットが必要です。

同じワークツリーのタスクが終了したら **独立ワークツリー → 反映をプレビュー** でパッチと競合を確認し、**ワークスペースへ反映** します。プレビュー後の変更や既存の編集があれば反映を拒否します。最大 20 件、各 512 KB の UTF-8 ファイルに対応します。それ以上、バイナリ、特殊な権限、競合は Git や外部エディターで処理してください。元のワークスペースで再検証します。反映の取り消しは後から加えた編集を上書きしません。

保存して削除する操作は追跡済み・未追跡ファイルをローカルに保存してからチェックアウトを削除します。無視対象は含みません。中断タスクは先にキャンセルしてください。復元すると保存したファイルを確認したり新しいフォローアップを実行できます。旧承認や未完了の実行を復活させるものではありません。

## 会話の整理

**タスクを管理** から名前変更、エクスポート、アーカイブ、削除を行います。履歴でアーカイブ済みタスクを表示できます。**会話をインポート** は Hikari JSON を読み込みます。同期スナップショットの **ローカルで続行** は新しいローカル会話を作成します。次の会話で開発ツールを使う場合は、先にローカルのワークスペースを選んでください。

インポートした質問と過去の回答は参考情報です。添付、実行状態、承認、過去の検証は復元しません。必要なファイルを再添付し、現在のワークスペースを確認してください。エクスポートにキー、画像内容、非公開の実行状態は含めません。タスク削除ではプロジェクトのファイルを削除しません。関連ワークツリーは先に保存してください。サイドバーの **最近のワークスペース** から以前のプロジェクトを開けます。

## 記憶と権限

**記憶と拡張機能** で記憶のタイトル、内容、出典、有効期限を編集または削除します。期限切れの記憶も確認できますが検索からは除外します。長いタスクでは目標、制約、判断、未解決事項、証拠を要約できます。

**保存済み権限** で承認を確認し、取り消せます。取り消すとその保存済み権限とセッション権限を解除します。実行中の処理は完了する場合がありますが、新しい要求には再承認が必要です。
